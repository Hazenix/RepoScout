# 03: 单仓库 pr-hint 调研与报告展示

**What to build:** 让本机 harness 对一个已关注仓库调用现有 `pr-hint`，使用用户预先授权的“全量 GitHub 审查；feat → fix → refactor/perf；最多四项”参数，并在看板展示本轮报告、推荐机会和完成范围。保留 skill 的现有调研方法。

**Blocked by:** 01 本机看板与关注仓库。

**Status:** ready-for-agent

- [ ] 实际运行时只对指定已关注仓库调用 `pr-hint`，传入固定模式、贡献类型顺序和数量；不实现另一套机会判断。
- [ ] 报告、进度和截止时间可从看板打开；未完成、限流及核验不足被标为未完成，不显示为已核验机会。
- [ ] 验证定时 harness 的持续授权能否通过现有 skill 的逐次确认门禁；若不能，只调整调用门禁所需的最小描述，不改变研究步骤和判断标准，并记录验证结果。
- [ ] 通过 GitHub CLI 的正式登录流程取得所需访问权限；访问失败和 `HTTP 429` 保留英文错误与失败状态，不伪造成功报告。
